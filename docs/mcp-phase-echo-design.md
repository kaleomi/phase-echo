## 1. 一句话

一款浏览器竞技场 FPS：在霓虹竞技场 ECHO-7 中存活 10 波并击败首领 RESONATOR PRIME。核心机制是 **相位残影**：能量充满后按 Q，你被拉回 3 秒前的位置并回复这 3 秒损失生命的一半；同时一个“过去的你”原样重演这 3 秒的走位和每一发子弹（65% 伤害），吸引敌人火力，最后坍缩，把周围敌人吸到中心引爆。

## 2. 玩法

| 系统 | 内容 |
| --- | --- |
| 移动 | 加速度式地面移动、有限空中控制、土狼时间 + 跳跃预输入、2 次充能冲刺、4 个弹射板（弹道落点固定在中央高台）、低血量自动回复到 50% |
| 武器 | 脉冲步枪（全自动、无限备弹、弹道扩散随连射增长）· 冰雹霰弹（10 发固定花型弹丸、逐发装填、开火打断换弹保留已装弹）· 磁轨长矛（105 伤害、贯穿 5 个目标、开镜 2.7 倍、可穿透壁垒护盾 55%） |
| 敌人 | 潜猎者（近身扑击，前摇闪烁）· 哨卫（保持距离，瞄准闪光后三连发）· 游魂（空中环绕，针刺）· 壁垒（正面 62° 护盾减伤 88%，背部散热口为弱点；远程迫击炮 + 近身震地波，跳起可躲） |
| 首领 | RESONATOR PRIME：悬浮核心 + 环绕护盾板；三阶段（100/66/33%），阶段切换有无敌过渡并清屏；五种前摇明确的攻击：环形弹幕、追踪光矛、螺旋弹幕、召唤、全场震地环（中央高台有独立内环） |
| 成长 | 每波结束 12 个模块三选一（伤害、换弹、弹匣、护甲、汲取、冲刺、共振、残影过载、弱点、连锁爆炸、拾荒、疾风），各有叠加上限 |
| 计分 | 连击窗口 4 秒、倍率上限 ×3、弱点击杀 ×1.5；波次奖励 = 基础 + 速度 + 无伤；难度倍率；S/A/B/C/D 评级；本地最佳纪录 |
| 难度 | 标准 / 困难 / 噩梦（敌人血量、伤害、数量、刷新速度、首领血量、得分倍率） |

## 3. 架构

```
game/phase-echo/
  index.html            入口（importmap 指向 node_modules/three）
  server.cjs            静态服务（默认 5190，PORT/HOST 可覆盖）
  src/sim/              纯规则层：不依赖 DOM / Three.js，可在 Node 无头运行整局
    geometry.js           射线-盒/球/胶囊、扫掠、圆-盒推出、线段距离
    layout.js             竞技场数据（碰撞盒、弹射板、8 个刷新门、补给点）
    physics.js            玩家与地面敌人共用的圆柱体运动学（子步进、台阶、弹射板弹道）
    nav.js                1 m 栅格 + 反向 Dijkstra 流场（两种体型；弹射板为单向边）
    player.js / weapons.js / enemies.js / boss.js / echo.js / waves.js / upgrades.js / scoring.js
    game.js               模拟总控：step(dt, input) → 状态 + 事件队列
  src/world/            Three.js 表现层：程序化贴图/模型、竞技场合批、特效池、第一人称视模、泛光后处理
  src/ui/               HUD、输入（指针锁定 + 未锁定回退）
  src/audio/sfx.js      WebAudio 全程序化音效 + 随强度变化的生成式配乐
  tests/                Node 规则测试 + 自动驾驶机器人 + Playwright 浏览器冒烟
```

设计要点：

- **规则与表现分离**：`src/sim` 只产生状态和事件（`shot`、`hit`、`kill`、`echoStart`…），渲染器只读状态、消费事件；整局可在 Node 里由机器人打完，用于回归测试。
- **固定步长**：模拟以 1/120 s 固定步长推进，输入的边沿动作只作用于每帧第一个子步。
- **稳定的着色器程序数**：场景灯光数量恒定（爆炸光用 3 盏预建灯池、残影灯常驻），避免运行时增删灯光导致全部材质重编译；运行中 programs 稳定在 13–15。
- **合批**：竞技场静态盒体与霓虹边按材质合并，整帧约 50–150 次绘制调用。
- **无外部素材**：所有贴图（Canvas）、模型（几何体拼装）、音效（振荡器/噪声/滤波）均为代码生成。

## 4. 操作

WASD 移动 · 鼠标瞄准 · 左键射击 · 右键瞄准（可在设置改为切换）· 空格跳跃 · Shift 冲刺 · 1/2/3 或滚轮切枪 · R 换弹 · Q 相位残影 · Esc/P 暂停。指针锁定失败时（嵌入页面、远程桌面）自动回退为直接移动鼠标转向，方向键也可转向。

### 7.1 过程中的失败与修复（保留记录）

1. 第一次 Windows 运行：SwiftShader 下在“清波/首领”阶段页面崩溃（Target crashed），前 6–8 步通过。
   - 定位：运行期不断新建/销毁带独立材质的特效、增删点光源，导致着色器程序反复销毁与重编译（programs 计数随战斗上涨），软件光栅化的 JIT 内存持续增长。
   - 修复：爆炸光改为 3 盏预建灯池、残影灯常驻；首领灯复用竞技场核心灯；所有特效对象（曳光、闪光、环、冲击波、标记、弹体、光矛）对象池化且永不 dispose 材质；模型几何体按参数缓存共享；开局前 `renderer.compile` 预编译全部变体。修复后 programs 在整局中不再增长。
2. 第二次 Windows 运行（修复 1 后）：SwiftShader 下仍在首领阶段崩溃一次（高画质：阴影 + 泛光）。
   - 结论：软件渲染无法承担高画质的首领场景。新增“自动”画质：检测到 SwiftShader / llvmpipe 等软件光栅器时默认低画质，GPU 上默认高画质。修复后两种模式均 12/12。
3. 浏览器测试早期以真实时间等待，软件渲染仅约 10 FPS 导致超时；改为 `window.__phaseEcho.advance()` 以固定步长快进游戏时间，测试结果不依赖帧率。

## 8. 2026-10 迭代：优化与新玩法

### 8.1 修复与优化

| 项 | 问题 | 处理 |
| --- | --- | --- |
| 高刷新率丢键 | 模拟固定 120 Hz，但每帧读取输入后都会清空单次动作；不推进模拟的帧（144 Hz 约 1/6，240 Hz 约 1/2）里的跳跃、冲刺、Q、换弹、半自动扳机会丢失 | 单次动作保持锁存，直到某个模拟步消费后才清空（`input.consume()`） |
| 开局/重开卡顿 | 每局重新光栅化两张导航网格（约 100 ms） | 场地与导航网格每页面只建一次，所有对局共享（只读） |
| 寻路尖峰 | 玩家与残影同时跨格时一步内最多 4 次 Dijkstra | 入边改为 CSR 数组 + 内联类型化数组堆（约 1.0 → 0.36 ms/次）；每步最多重算 1 张流场（轮转） |
| HiDPI 模糊 | 后处理合成器在构造时记下像素比 1，之后从未更新；高/中画质在高分屏上以 1 倍渲染后拉伸 | 画质切换时同步 `composer.setPixelRatio` |
| 动态分辨率 | 自动画质只区分软件/硬件渲染 | 自动画质（GPU）下按 1 秒窗口测帧率，低于 50 fps 下调渲染比例（最低 0.5），持续流畅后回升 |
| 死亡镜头 | 2.2 秒死亡镜头按每帧最多 0.1 秒累计，帧率很低时会拖长到数十秒 | 改用真实时间 |
| 测试偶发失败 | 测试机器人使用 `Math.random`，整局测试约 1/6 概率误报 | 机器人改用以对局种子派生的随机数，结果可复现 |

### 8.2 新玩法（全部在 `src/sim` 规则层实现，可无头测试）

- **相位换位**（`game.js` `phaseSwap`）：重演开始 0.35 秒后再次按 Q，玩家与残影互换位置，残影立即在玩家原位置坍缩（`collapseEcho`），0.35 秒无敌；每个残影限一次。
- **悖论击杀**：敌人记录最后一次被玩家/残影命中的时间；1 秒内两者都命中过的击杀得分 ×1.5、回复 10 能量。
- **残影改造模块**（`upgrades.js`，`echo: true`）：延时残影（窗口 3→4 秒、坍缩 +20%）、相位虹吸（残影每承受一次攻击为玩家充能 6）、换位冲击（换位后 2.5 秒伤害 +40%、补满冲刺）。
- **首领光矛锁定残影**：残影重演时，RESONATOR PRIME 的光矛有一半概率追踪残影；光矛命中残影触发 `echoHit`。
- **逆时体 REWINDER**（`enemies.js`）：飞行单位，10 Hz 记录自身位置与血量；每 5 秒（0.75 秒前摇：沙漏翻转、指针倒转、锚点闪烁）回溯到 3 秒前并恢复期间损失的生命。距本体 1.3 米以上的“时间锚点”可被射击击碎（取消本轮回溯、0.7 秒硬直、35 伤害）；残影坍缩的牵引也会抹除锚点。发射成对的时序弹。第 4、6、7、8、9 波出现。
- **每日挑战**（`daily.js`）：UTC 日期 → FNV-1a 种子；6 种变异规则按天轮换（相位风暴、玻璃大炮、逆时潮汐、军火库、精英潮、疾风），以属性或难度修正实现。刷怪队列、刷怪间隔、刷怪门和模块选项各用独立的种子子流（`rng.streamSeed`），不受玩家操作消耗的随机数影响——打法不同的两局在每一波看到相同的敌人和（相同选择下）相同的模块。
- **最佳残影**（`ghost.js`）：10 Hz 位姿轨迹（厘米/厘弧度整数、差分编码，约 6.6 KB/分钟）+ 每波通关时间；每个模式（标准/困难/噩梦/当日每日挑战）保存最佳一局，下次以金色身影重放并显示每波时间差。旧的每日记录自动清理；作弊参数（`?god`、`?wave=`）不写入纪录。

### 8.3 独立审查后的修正

另起一个代理只读审查全部改动，确认并修正了：每日挑战从第 2 波起因共享随机数而分叉（改为独立子流，并补了“两种打法逐波对比”的测试）；动态分辨率把 50 Hz 屏幕或浏览器省电 30 fps 上限误判为显卡过载（改为以实测刷新上限为参照，目标为 min(上限, 60)）；相位换位的瞬移被录进下一次残影（换位时清空记录）；残影射击击碎锚点时按玩家伤害计算且提示文案错误；爆炸对残影的判定缺少高度和遮挡检查（会给相位虹吸白送能量）；`?fast` 测试参数仍能写入纪录。
